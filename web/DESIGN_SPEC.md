# Career Radar Web 管理端 — 设计规范（唯一实现依据）

> 本文档是前端实现的完整需求与设计规范。任何页面、组件、交互、文案均以本文档为准。

## 一、项目背景

Career Radar 是一款面向 2026 届校招求职者的企业官网招聘信息自动监控系统。系统每天自动访问用户配置的企业公开官网，识别"招聘""加入我们"等入口，进入招聘列表页和职位详情页，通过 LLM 提取完整 JD，使用 SQLite 对岗位进行去重和变化检测，最终生成 Markdown、CSV 日报，并可根据用户画像筛选岗位和发送邮件提醒。

系统核心价值：把"每天手动查看多家企业官网是否发布新岗位"这件事自动化，只展示真正新增、发生变化并且与用户画像匹配的岗位。

后端已完成的能力：企业官网监控、robots.txt 合规检测、requests 静态抓取、Playwright 动态渲染回退、招聘入口自动发现、LLM 岗位信息提取、URL 真实性校验、SQLite 岗位去重与变化检测、Markdown/CSV 日报生成、邮件通知、用户画像匹配、岗位难度评估、运行日志记录、单公司失败隔离。本任务只实现前端（Mock 数据 + API Service 层）。

## 二、设计定位

参考苹果官网和小米高端产品官网的气质，但不直接模仿任何现有页面。关键词：简约、高级、克制、清晰、可信、安静、专业、高信息密度但不拥挤、面向真实求职用户而不是技术开发者。

不要设计成传统后台管理系统：禁止大面积深蓝色侧边栏、廉价渐变、过度圆角、密集边框、大量彩色图标。

界面需同时具备：苹果式的留白/层级/精细排版；小米官网式的产品化表达、醒目数字、简洁卡片；SaaS 产品的效率与信息可读性；求职产品的温度与行动引导。

用户进入系统 5 秒内应明白：今天发现了多少新岗位；哪些岗位最适合自己；系统上次什么时候运行；哪些公司抓取失败；下一步应该点击什么。

## 三、技术栈与工程要求

- React 19 + TypeScript + Vite + Tailwind CSS 3.4 + shadcn/ui（已预装 40+ 组件于 `src/components/ui/`）
- 路由：`react-router` v7（已安装，直接从 `react-router` 导入，不要装 react-router-dom）
- 数据请求：TanStack Query（已安装 `react-router`、`@tanstack/react-query`、`recharts`、`lucide-react`、`sonner`、`next-themes`）
- 图标：Lucide（16px 或 18px 线性图标）；图表：Recharts（仅在有真实价值处使用，禁止无意义图表）
- 组件化结构、完整路由、Mock 数据独立于页面组件（放 `src/mocks/`）、数据请求封装在 `src/services/`（模拟异步延迟，预留 baseURL 切换真实 Python 后端）、类型定义集中在 `src/types/`
- 桌面端优先，适配平板与手机；支持浅色模式，代码结构预留深色模式能力（CSS 变量 + next-themes，暗色变量留好即可，不需要做暗色切换 UI）
- 所有按钮必须有 hover、active、disabled、loading 状态
- 所有列表必须设计：加载（Skeleton）、空数据、错误、搜索无结果 四类状态
- 不要把大量数据硬编码在页面组件中

## 四、全局视觉规范

### 色彩系统

- 页面背景 `#F5F5F7`；内容卡片 `#FFFFFF`；次级背景 `#FAFAFA`
- 文字：主标题 `#1D1D1F`；正文 `#333336`；次级说明 `#6E6E73`；弱化 `#8E8E93`
- 品牌主色 Career Blue `#1677FF`；Hover `#0958D9`；浅色背景 `#EAF3FF`
- 状态色：成功 `#22A06B`；警告 `#D97706`；错误 `#D92D20`；信息 `#1677FF`
- 辅助强调橙 `#FF6900` 仅用于"高度推荐""AI 匹配"等极少数位置；不允许整页同时出现多个高饱和主色
- 禁止大面积渐变；允许首页欢迎区使用极轻微、几乎不可察觉的蓝灰色光晕

### 字体

系统字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Display", "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif`

字号：页面主标题 32px；页面副标题 16px；卡片关键数字 32px；模块标题 20px；正文 14px；辅助文字 12px。标题行高 1.3，正文行高 1.6。

### 圆角与阴影

大卡片 16px；普通卡片 12px；输入框/按钮 10px；标签 6px。

阴影必须克制：`0 1px 2px rgba(0,0,0,0.03), 0 8px 24px rgba(0,0,0,0.04)`。优先用背景层级和留白区分区域，不要给每个元素加边框。

### 图标

图标只作辅助信息，不能代替文字。所有重要按钮必须同时显示文字；16/18px 线性图标；不拟物、不彩色插画；同页风格统一。

## 五、全局布局

桌面端：左侧固定导航 224px；顶部操作栏 64px；主内容最大宽度 1440px；内容区左右内边距 32px；模块间距遵循 8px Grid。

侧边栏用白色或浅灰白背景，禁止深色。顶部左侧显示当前页面名称；右侧：全局搜索、最近运行状态、通知入口、用户头像/菜单。

左侧导航（7 项）：总览、岗位中心、企业监控、运行中心、日报中心、用户画像、系统设置。

侧边栏底部：系统版本、GitHub 项目入口、"服务运行正常"状态。

移动端隐藏侧边栏，改顶部菜单或底部核心导航。

## 七、页面详细设计

### 页面一：首次使用引导 `/onboarding`

用户第一次进入系统时看到的页面，不需要注册登录。顶部只显示 Career Radar 文字标识和"跳过配置"。居中步骤式引导，共 4 步。

**第 1 步：建立求职画像** — 字段：毕业届别、学历、专业、目标岗位方向（可搜索多选：AI 应用 / 数据分析 / 产品助理 / 测试 / 运维 / 后端开发 / 前端开发 / 内容运营 / 其他）、期望城市、薪资范围、当前技能、是否接受实习、是否接受异地、最大岗位难度。按钮：返回、保存并继续。

**第 2 步：添加监控企业** — 推荐企业卡片（企业名称、简称、官网地址、招聘入口、所属行业、当前监控状态）；支持勾选推荐企业、手动添加企业、批量导入、测试招聘入口。按钮：返回上一步、添加自定义企业、保存并继续。

**第 3 步：设置扫描规则** — 每日运行时间、同域请求间隔、是否启用 Playwright 自动回退、单家公司最大页面数、是否仅保留校招和实习岗位、是否启用岗位变化检测。默认值安全、合规、保守。

**第 4 步：通知方式** — 是否生成 Markdown 日报、是否生成 CSV 日报、是否启用邮件提醒、通知哪些类型岗位、最大岗位难度、最低能力匹配等级。最后按钮：完成配置并开始首次扫描。

首次扫描前弹提示："首次扫描会将企业官网现有岗位建立为基线，可能产生较多'新增岗位'记录。建议首次运行不发送邮件。"按钮：仅建立基线 / 建立基线并发送通知。

### 页面二：总览 Dashboard `/`（最重要页面）

**头部**：左侧标题"早上好，今天有 3 个新机会"（按时段变化问候语）；副标题"Career Radar 已为你监控 10 家企业，上次扫描完成于今天 09:47"。右侧主按钮"立即扫描"，次按钮"查看运行记录"。点击立即扫描弹确认框：扫描全部企业 / 仅扫描失败企业 / 本次不发送邮件（复选）/ 开始扫描。扫描期间按钮显示进度"正在扫描 3 / 10 家企业"。

**第一行：关键数据卡片（4 个）**：今日新增岗位、今日更新岗位、高匹配岗位、监控企业。每张卡片：核心数字（醒目）、与昨日变化、简短解释、点击跳转对应筛选结果。不要复杂图表。

**第二行：AI 推荐岗位** — 模块标题"最适合你的岗位"，3~5 个岗位卡片。每卡：职位名称、企业名称、地点、实习/校招标签、届别匹配、能力匹配、难度评分、更新时间、推荐原因（自然语言，如"该岗位要求 RAG、工作流和 AI Agent，与当前项目经历匹配度较高"）、查看详情按钮、收藏按钮。高推荐岗位可用极轻的浅橙色标签，整卡不能变橙。

**第三行左侧：最近岗位变化** — 时间线或精简列表：新增岗位 / JD 更新 / 招聘入口变化 / 岗位关闭。每条：变化类型、岗位名称、企业、变化时间、查看变化按钮。

**第三行右侧：扫描运行状态** — 最近一次运行：开始/结束时间、总耗时、成功企业数、跳过数、失败数、新增岗位、更新岗位。下方企业扫描进度列表（如 FIT2CLOUD：成功；EMQ：等待扫描；SmartX：失败；NebulaGraph：robots 禁止），点击进运行详情。

**底部：需要关注** — 只显示真正需处理事项，每条带明确操作按钮：3 家企业尚未完成首次验证（立即验证）、SMTP 尚未开启（前往设置）、离线测试尚未运行（运行测试说明）、1 家企业连续两次抓取失败（查看失败原因）。

### 页面三：岗位中心 `/jobs`

顶部：标题"岗位中心"，副标题"查看新岗位、岗位变化以及与个人画像的匹配情况"。右侧按钮：导出当前结果、刷新岗位。

**标签页**（带数量）：推荐、新增、已更新、全部岗位、收藏。

**搜索筛选区**：搜索框（职位名称/公司名称/JD 关键词/技能关键词）；筛选：企业、城市、岗位类型、届别匹配、能力匹配、难度区间、新增或更新、发布时间、是否有投递链接；操作：重置筛选、保存筛选条件。

**列表**：表格与轻量卡片融合。列：职位（名称 + 一行简短推荐理由）、企业、地点、匹配度（高匹配/中匹配/低匹配/信息不足，不只显示百分比）、难度（2/10、5/10、8/10 样式）、状态、更新时间、操作（查看详情、收藏、打开官网、更多：标记已投递/标记不感兴趣/复制岗位信息/忽略本次更新）。支持多选：批量收藏、批量导出、批量标记不感兴趣。

**空状态**：不只写"暂无数据"。显示"暂时没有符合当前条件的岗位。"+ 按钮：清除筛选条件 / 调整求职画像 / 立即扫描企业。

### 页面四：岗位详情 `/jobs/:id`

顶部返回岗位中心。**岗位信息区**：职位名称、企业名称、城市、工作类型、发布时间、首次发现时间、最后更新时间、新增/更新状态、届别匹配、能力匹配、难度评分。右侧主按钮"前往官网投递"；次级：收藏岗位、复制信息、标记已投递。无有效 apply_url 时不显示不可用投递按钮，改为提示"当前页面未识别到可信投递链接，请查看 JD 中的联系方式。"+ 按钮：打开来源页面、复制 JD 中的邮箱。

**主体左侧**分区：岗位概览、工作职责、任职要求、加分项、工作地点、投递方式、完整 JD 原文（良好排版，不是一整块长文本）。

**主体右侧固定侧栏**：

- 模块一 AI 匹配分析：综合匹配结论、已具备能力、缺失能力、建议优先补充内容、是否建议投递（示例："建议投递。你的 RAG 项目经历与岗位方向相关，但需要补充工作流编排和 MaxKB 的实际使用案例。"）
- 模块二 岗位难度：解释难度构成（技术要求、工作经验、学历要求、工具熟悉度、岗位竞争程度）
- 模块三 来源可信度：来源企业官网、来源页面、抓取方式、URL 是否通过页面候选校验、最后验证时间

**更新历史**：变化时间线（如 07-18 首次发现 / 07-20 任职要求变化 / 07-22 投递邮箱变化）+"查看差异"按钮。差异视图红绿对比（颜色克制），支持：只看新增 / 只看删除 / 查看完整版本。

### 页面五：企业监控 `/companies`

标题"企业监控"。顶部按钮：添加企业、批量导入、扫描全部企业。

每家显示：企业名称、官网地址、招聘入口、当前监控状态、最后扫描时间、最近发现岗位数、页面渲染方式、robots 状态、连续失败次数。状态枚举：正常 / 扫描中 / 等待首次验证 / robots 禁止 / 页面结构异常 / 请求失败 / 已暂停。操作：立即扫描、查看详情、编辑、暂停监控；"删除企业"放更多菜单，不直接暴露。

**添加企业弹窗**字段：企业名称、企业官网、招聘入口（可留空自动发现）、渲染模式（自动/静态/动态）、最大扫描页面数、是否启用、企业备注。按钮：测试连接、保存企业。测试连接结果展示：robots 是否允许、首页是否可访问、是否识别到招聘入口、是否需要浏览器渲染、预计可发现页面数量。

### 页面六：企业详情 `/companies/:id`

顶部企业基础信息和状态；主按钮：立即扫描、编辑配置、暂停监控。模块：企业监控概览、最近发现岗位、扫描页面记录、招聘入口识别结果、robots 检查结果、最近错误、企业运行历史。

扫描页面记录列：页面 URL、页面类型、抓取方式、HTTP 状态、页面正文长度、是否进入 LLM 提取、抓取时间。错误记录用人话（如"页面返回 403，系统按照合规策略未继续尝试。"）+"查看技术详情"折叠区。

### 页面七：运行中心 `/runs` + `/runs/:id`

标题"运行中心"，右侧按钮"新建扫描任务"。任务列表列：任务编号、运行方式、开始/结束时间、进度、成功企业数、失败企业数、新增岗位、更新岗位、邮件状态、任务状态（等待中/运行中/已完成/部分完成/已中断/失败）。点击进入详情。

**运行详情**顶部实时进度"正在扫描 SmartX，已完成 4 / 10 家企业"；操作：停止任务、仅重试失败企业、下载日志。按企业展示执行过程步骤：robots 检查、首页抓取、招聘入口识别、招聘列表抓取、职位详情抓取、LLM 提取、数据去重、日报生成、邮件通知。每步：成功/跳过/失败、执行时间、简要说明。不默认展示大量原始日志；原始日志放"技术日志"折叠区，支持搜索、错误级别筛选、复制、下载。

### 页面八：日报中心 `/reports` + `/reports/:date`

标题"日报中心"，右侧"立即生成日报"。顶部筛选：日期选择、报告类型、是否只看匹配岗位、企业筛选。列表列：日期、新增岗位数、更新岗位数、高匹配岗位数、Markdown 状态、CSV 状态、邮件发送状态。操作：查看日报、下载 Markdown、下载 CSV、重新发送邮件。

**日报详情**双视图：阅读模式 / 数据表模式。阅读模式像高质量求职情报简报：今日摘要、最推荐岗位、新增岗位、更新岗位、企业扫描异常、明日关注建议。数据表模式看完整字段。CSV 下载按钮旁提示"文件使用 UTF-8 BOM，可直接使用 Excel 打开。"

### 页面九：用户画像 `/profile`

标题"我的求职画像"，左右两栏。左侧基础信息：届别、学历、专业、目标岗位、期望城市、薪资区间、可接受工作类型、最大岗位难度。右侧能力标签：Python、SQL、RAG、LLM 应用、数据分析、Flask、Git、Linux、前端基础、产品能力、内容运营；支持添加技能、设置熟悉程度、删除技能、添加项目经历、添加不感兴趣方向。底部固定操作栏：放弃修改、保存画像、保存并重新计算匹配度。顶部画像完整度："当前画像完整度 78%，补充项目经历可提高岗位匹配准确性。"

### 页面十：系统设置 `/settings`（多标签）

- **基础设置**：系统时区、输出目录、数据库位置、每日运行时间、日报保留天数
- **抓取设置**：同域最小/最大延迟、默认渲染模式、页面正文最低长度、单家公司最大页面数、请求超时、是否遵循 robots.txt（默认开启，不允许普通用户随意关闭——用禁用态 + 说明呈现）
- **LLM 设置**：服务商（DeepSeek/OpenAI/Anthropic）、模型名称、API Base URL、API Key 状态（只显示"已配置 ····a82f"，前端永不返回完整 Key）、JSON Output、最大切片长度、切片重叠长度、超时时间、重试次数。按钮：测试连接、保存设置
- **邮件通知**：启用邮件、SMTP 主机/端口/加密方式、发件/收件地址、发送条件、最低匹配等级、最大难度、是否发送更新岗位。按钮：发送测试邮件、保存设置。SMTP 未启用时清晰提示："邮件通知当前未启用，Markdown 和 CSV 日报仍会正常生成。"
- **数据与维护**：数据库统计、导出全部数据、清空运行日志、重建岗位索引、重新计算岗位匹配度、清理历史日报。危险操作二次确认并说明影响范围

### 页面十一：通知中心 `/notifications`

通知类型：高匹配新增岗位、监控企业连续失败、扫描任务完成、日报生成成功、邮件发送失败、配置错误、系统更新提示。支持：全部已读、单条已读、删除、跳转相关页面。通知用用户语言，禁止技术报警原文。错误示例：不写"ValueError in pipeline.py line 184"，应写"SmartX 的招聘页面暂时无法解析，本次扫描已跳过，不影响其他企业。"

### 页面十二：全局搜索

顶部搜索框支持搜：岗位、企业、技能关键词、城市、运行记录。结果分类：岗位、企业、日报、运行记录。快捷键：Ctrl/Cmd+K 打开、上下方向键移动、Enter 打开、Esc 关闭（用 cmdk/Command 组件实现全局搜索弹窗，`/search` 页面展示完整结果）。

## 八、关键交互要求

1. **操作反馈**：所有操作有明确反馈（保存成功/扫描任务已创建/企业配置已更新/岗位已收藏/邮件发送失败/报告已下载），用 Toast（sonner）、确认弹窗、行内提示，禁止浏览器原生 alert。
2. **加载状态**：扫描和 LLM 提取耗时长，禁止只显示无限转圈；显示真实步骤，如"正在检查 robots.txt / 正在识别招聘入口 / 正在分析 3 个职位详情页 / 正在合并岗位信息 / 正在生成日报"。
3. **错误状态**：错误页必须提供：用户可理解的原因、是否影响其他企业、推荐操作、重试按钮、查看技术详情入口。
4. **空状态文案差异化**：岗位为空"还没有发现符合画像的岗位，可以尝试降低匹配条件或添加更多企业。"；企业为空"还没有监控企业，添加第一家企业后，Career Radar 会自动寻找招聘入口。"；日报为空"完成第一次扫描后，系统会在这里生成岗位日报。"

## 九、按钮层级（每页最多一个最突出主按钮）

- **主按钮**（品牌蓝实心）：立即扫描、保存设置、前往官网投递、添加企业、完成配置
- **次级按钮**（白底浅边框）：查看记录、导出、测试连接、复制、编辑
- **文字按钮**：查看全部、展开详情、清除筛选、返回
- **危险按钮**：删除企业、清空数据、停止任务——默认不大面积红色，只在确认弹窗内突出
