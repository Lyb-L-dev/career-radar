## 修复的真实漏岗原因

1. Dify 静态招聘页同时包含加载状态与空列表提示，但真实岗位来自 JSON。直接读静态文案可能误判无岗位，现接入官网已引用的接口。
2. JSON Feed 原先只发一次请求。新增显式页码字段、总数路径、页数上限，逐页执行 robots、限速与取消检查；重复页、记录重叠、总数变化、提前空页或达到上限时失败，避免静默截断。
3. 首轮 71 条来源记录仅产生 67 条新增，核对发现旧模糊去重把合合信息 4 个不同官方 ID 的相似岗位合并。现保留来源命名空间与岗位 ID；不同 ID 不做模糊合并，同 ID 改名仍更新同一实体。再次采集恢复 4 条，总数达到 137。旧无 ID 同名记录的升级保留原主键和用户状态，官方完整事实可替换旧合并正文。模型猜测的 ID 在合并前清除。

没有下载整套爬虫项目或新增重叠爬虫框架，本轮使用已有 JSON Feed、Requests、BeautifulSoup、存储和前端数据转换。公开且可复现的公司配置位于 [official_source_presets.yaml](../data/official_source_presets.yaml)。网络探针原始公开样本保留在本机忽略目录 `tmp/official-2026-10-04/`，报告的实时数量只能代表此次采集时的官网响应。
